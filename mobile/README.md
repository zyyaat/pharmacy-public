# Pharmacy OS — التطبيق المحمول (Flutter)

تطبيق الصيدلية للـ Android مبني بـ Flutter، والمبدأ الأساسي: **لا تحتاج أي بيئة على جهازك**.
الكود كله هنا، والبناء يتم سحابيًا عبر GitHub Actions، وتستلم ملف APK جاهزًا للتثبيت.

---

## 1) كيف تبني APK بنقرة واحدة

1. افتح صفحة المستودع على GitHub → تبويب **Actions**
2. من القائمة الجانبية اختر **flutter-build**
3. اضغط زر **Run workflow** (أعلى يمين القائمة)
4. (اختياري) أدخل `api_base_url` — اتركه فارغًا وسيُستخدم خادم الإنتاج تلقائيًا:
   `https://pharmacy-public.dockhosting.dev/api/v1`
5. اضغط **Run workflow** وانتظر انتهاء البناء (~10 دقائق أول مرة)
6. من صفحة التشغيل نفسها، في قسم **Artifacts** أسفل الصفحة ستجد حزمتين — اختر حسب جهازك:
   - **`pharmacy-mobile-apk-arm64-<رقم التشغيل>`** ← **هذه المطلوبة لأغلب الهواتف**
     (كل الهواتف الحديثة تقريبًا، وبداخلها `app-arm64-v8a-release.apk`)
   - `pharmacy-mobile-apk-universal-<رقم التشغيل>` ← احتياط للأجهزة القديمة جدًا
     (بداخلها `app-release.apk` بكل المعماريات)
7. انقل الملف لجهازك وثبّته (اسم التطبيق الظاهر: **Pharmacy OS**)

> **التحديث فوق النسخة المثبتة يعمل مباشرة**: كل بناء موقّع بمفتاح إصدار ثابت
> (Keystore محفوظ في GitHub Secrets) ورقم الإصدار `versionCode` يزيد مع كل تشغيل
> (يساوي رقم التشغيل)، فثبّت الحزمة الجديدة فوق القديمة دون حذف، وسيتحدّث التطبيق
> محافظًا على بياناتك وجلستك.
> — استثناء لمرة واحدة فقط: إن كانت النسخة المثبتة لديك من بناءات قديمة (قبل
> التوقيع الثابت) فاحذفها أولًا يدويًا ثم ثبّت الجديدة، لأن أندرويد يرفض التحديث
> فوق مفتاح توقيع مختلف.

> لماذا حزمة arm64 مخصصة؟ الحزمة الشاملة تحتوي مكتبات 32-bit إضافية قد يرفضها تثبيتها
> أحدث الأجهزة (بنوى صفحات 16KB)، بينما حزمة **arm64-v8a** خفيفة ومتوافقة مع كل
> الهواتف الحديثة ومبنيّة بتغليف يضمن نجاح التثبيت دائمًا.

> يوجد أيضًا بناء تلقائي: أي Push يمس `mobile/**` يشغّل البناء تلقائيًا بنفس الإعدادات.

## 2) متغيرات البيئة — طبقتان للمطورين

| الطبقة | أين | متى تستخدمها |
|---|---|---|
| **1. GitHub Variable** | Settings → Secrets and variables → Actions → تبويب **Variables** → أضف `API_BASE_URL` = عنوان الـ API | **الأفضل**: تُضبط مرة واحدة وتعمل مع كل بناء تلقائي |
| **2. إدخال التشغيل** | خانة `api_base_url` عند Run workflow | لتجربة خادم مختلف لبناء معين دون تغيير إعداد المستودع |

ترتيب الأولوية: **إدخال التشغيل → متغير المستودع → القيمة الافتراضية المدمجة**.

> ⚠️ **عنوان الخادم للمطورين فقط** — لا يوجد أي تحكم به داخل التطبيق إطلاقًا؛
> العميل لا يستطيع تغييره من الشاشات، فالتغيير يتم قبل البناء حصرًا.

آلية الحقن تقنيًا: الـ workflow يكتب `env.json` ثم يمرره للبناء عبر
`--dart-define-from-file=env.json`، والكود يقرأه في `lib/config.dart` عبر
`String.fromEnvironment('API_BASE_URL')`. هذا كل شيء — لا ملفات `.env` ولا مفاتيح سرية
حساسة هنا (التطبيق لا يحتفظ بأي سر؛ الجلسة كوكيز من الخادم).

> المستودع يتطلب HTTPS لعنوان الـ API — نطاق الإنتاج موقّع بشهادة سليمة فلا مشكلة.

## 3) ماذا يغطي الإصدار الأول (v1.0.0)

- **دخول** بجلسة كوكيز معتمة (نفس آلية الويب حرفيًا) + تجديد تلقائي للجلسة عند انتهائها
- **تسجيل حساب صيدلية جديد** + شاشة رمز التحقق (OTP) — وبعد التحقق تدخل مباشرة
  (نفس «التسجيل الذكي» من Task 57: الجلسة تُفتح من الخادم فور التأكيد)
- **معالج إعداد الصيدلية** بأسلوب Upwork: 4 خطوات، تخطي للاختياري، مراجعة بتعديل قافز
- **اللوحة**: إحصاءات (الأصناف، شبه النافد، الموظفون، مبيعات اليوم) + قائمة الأصناف شبه النافدة
- **الأدوية**: بحث بالاسم/الباركود مع مؤجل 400ms، أسعار علبة/شريط، حالة المخزون
- **الإعدادات**: العربية/English (محفوظة محليًا وعلى الحساب)، تسجيل خروج
- **جلسة دائمة**: تبقى مسجلاً دخول حتى تسجّل الخروج بنفسك — فساد الكوكيز يعالجه
  دخول صامت بالبيانات المحفوظة مشفّرة، وانقطاع الشبكة لا يُخرجك أبدًا

## 4) خريطة الكود

```
mobile/
├── lib/
│   ├── main.dart                 التطبيق + التوجيه + المزودون
│   ├── config.dart               قراءة --dart-define (API_BASE_URL)
│   ├── core/
│   │   ├── api_client.dart       dio + نقاط النهاية + تجديد 401 تلقائيًا
│   │   ├── cookies.dart          جلسة الكوكيز اليدوية (absorb/send/persist)
│   │   ├── session_store.dart    تخزين آمن: بيانات الدخول + اللغة + الثيم
│   │   └── strings.dart          i18n مصغّر ar/en بلا كود توليد
│   ├── models/models.dart        User/Product/Stats/Onboarding (تحليل دفاعي)
│   ├── state/app_state.dart      AuthProvider (آلة حالات الجلسة) + LocaleProvider
│   ├── screens/                  splash / login / register / verify / onboarding / home
│   └── widgets/ui.dart           الهوية البصرية المشتركة
├── scripts/prepare_android.sh    ترقيع android/ المولود (شبكة + اسم + minSdk 23 + تغليف + توقيع ثابت)
└── test/                         smoke + هيكل الصفحات + سلوك الجلسة الدائمة
```

لماذا مجلد `android/` غير موجود؟ **مقصود**: يُولّد في كل بناء من قالب نسخة Flutter
المثبتة في الـ workflow (`flutter create`) ثم يرقّعه `prepare_android.sh` — هكذا لا
يتقادم الغلاف/الإضافات ولا يحتاج صيانة، وتبقى الشبكة (CI) مصدر الحقيقة الوحيد.

## 5) لماذا جلسة كوكيز لا Bearer؟

خادمنا يصادق بجلسة كوكيز معتمة (pharmacy_access / pharmacy_refresh / pharmacy_csrf)
ولا يقبل ترويسة Authorization إطلاقًا — لذا التطبيق يمتص `Set-Cookie` من كل استجابة ويعيد
إرسالها، ويحقن `X-CSRF-Token` من كوكي CSRF في كل طلب تغيير، مع مسح الكوكي حين يرسل
الخادم `Max-Age=-1`. التخزين عبر flutter_secure_storage مشفّر على الجهاز.

## 3) الميزات — تكامل كامل مع تطبيق الويب (Task 61)

التطبيق يغطي **كل صفحات تطبيق Next.js** بنفس الترتيب والصلاحيات:

| القسم | الشاشات |
|---|---|
| **الجلسة** | إقلاع بفحص الجلسة، دخول، تسجيل بمعالج 4 أسئلة، تحقق OTP بجلسة فورية، معالج إعداد الصيدلية (Upwork-style) |
| **اللوحة** | 4 بطاقات إحصائية بالنغمات، إجراءات سريعة، حالة المخزون، النشاط الأخير |
| **نقطة البيع** | بحث ذكي + باركود، سلة بوحدات (علبة/شريط)، خصم نسبة/مبلغ، نقدي/آجل بعميل، إيقاف مؤقت للفواتير، إيصال حراري |
| **المبيعات** | سجل بالبحث والترقيم، تفاصيل الفاتورة، استرجاع أصناف بكميات متاحة |
| **المخزون** | تشغيلات بحالات (متوفر/منخفض/نافد/صلاحية)، تفاصيل منتج، تسوية مخزون بسبب، إضافة/تعديل منتج كامل الحقول |
| **الحركات** | سجل كامل بفلاتر النوع والاتجاه والتاريخ والبحث |
| **العملاء** | قائمة + إضافة، ديون الآجل، كشف حساب، تحصيل دفعات |
| **الموظفون** | قائمة، إضافة بقالب صلاحيات، محرر صلاحيات بالنطاقات، إيقاف/تفعيل |
| **الحضور** | سجل الدخول والخروج بالمدد |
| **الفروع** | قائمة، إضافة/تعديل، إيقاف، مزامنة الفرع الرئيسي باسم الصيدلية |
| **التقارير** | مبيعات (KPIs + رسم يومي + الأكثر بيعًا)، مخزون (قيم + نواقص + صلاحيات)، حركات (ملخص بالنوع) — بفترات جاهزة |
| **الإعدادات** | الفواتير والطباعة (مقاس ورق، محتوى، معاينة)، قاعدة البيانات (الترحيلات)، اللغة، **ترحيل المنتجات من Excel/CSV** بثلاث خطوات |

- **التصميم**: نفس هوية الويب حرفيًا — الألوان مُحوّلة رياضيًا من oklch (أخضر `#008D4D` / `#00B56D` داكن)، نفس البطاقات والشارات والنغمات (amber/emerald/blue)، وضع ليلي كامل، RTL تلقائي.
- **اللغة**: نفس قاموس الويب (1026 مفتاحًا ar/en) مولّد آليًا عبر `scripts/mobile_i18n_generate.py` — أي تعديل نصوص في الويب ينعكس بأمر واحد.
- **النقود**: كل المبالغ بياسترات صحيحة داخليًا (1 ج.م = 100 بياسة)، أرقام لاتينية دائمًا، «ج.م» عربي / «EGP» لاتيني — قواعد Task 47/48 نفسها.
- **الصلاحيات**: القائمة والإجراءات تخفى بنفس مفاتيح permissions.catalog كما يفعل الشريط الجانبي في الويب.
