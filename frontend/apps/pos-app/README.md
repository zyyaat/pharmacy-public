# Pharmacy POS — تطبيق نقطة البيع

تطبيق مستقل خفيف لنقطة البيع مع إدارة مخزون كاملة، من نفس مستودع ونفس منطق
`pharmacy-app` بالحرف: نفس جلسات الدخول، نفس نظام الصلاحيات المرن (مفاتيح
`pos.access` / `sales.view` / `inventory.view` / `inventory.manage_products` /
`inventory.adjust` / `inventory.movements.view`)، نفس الباك إند Go ونفس قاعدة
البيانات — بلا أي تكرار للمنطق في الخادم.

## الصفحات

| المسار | الوصف | الصلاحية |
|---|---|---|
| `/login` | دخول بنفس حساب الصيدلية | — |
| `/` | تحويل تلقائي إلى نقطة البيع | — |
| `/pos` | شاشة البيع الكاملة: بحث بالباركود/الاسم، السلة، آجل، إضافة عميل سريع، طباعة إيصال، فواتير معلقة | `pos.access` |
| `/sales` | سجل المبيعات | `sales.view` |
| `/sales/[id]` | تفاصيل الفاتورة: إعادة طباعة + استرجاع | `sales.view` + `sales.returns` للزر |
| `/inventory` | المخزون والأدوية: كل التشغيلات بالكمية/الصلاحية/الحالة + بحث + التحكم في الكميات (إضافة/خصم بسبب) | `inventory.view` + `inventory.adjust` لزر المخزون |
| `/inventory/new` | إضافة منتج جديد بمخزون افتتاحي وتشغيلة وصلاحية | `inventory.manage_products` |
| `/inventory/edit/[productId]` | تعديل بيانات المنتج (نفس نموذج الإضافة) | `inventory.manage_products` |
| `/inventory/movements` | سجل حركات المخزون: بيع/استرجاع/شراء/تسويات/إعدام بفلاتر بحث ونوع واتجاه وتاريخ | `inventory.movements.view` |
| `/settings` | الإعدادات: اختيار لغة الواجهة (يُحفظ دائمًا على الحساب) | — (متاح لكل الحسابات) |

الأزرار والأقسام الممنوعة مخفية كليًا (نفس بوابة `<Can>` / `<RequirePermission>`
والهيكل العظمي بلا وميض كما في التطبيق الرئيسي)، والفرض الحقيقي باقٍ في الباك إند.

## نظام اللغات (Task 48)

نظام i18n كامل بنفس البنية في كل التطبيقات (`src/i18n/`):

- **8 لغات** الأكثر استخدامًا عالميًا: العربية (الافتراضية RTL) وEnglish وFrançais
  وEspañol وTürkçe و中文 وहिन्दी واردو (RTL).
- **حفظ دائم على الحساب**: `PATCH /api/v1/auth/pharmacy/locale` يكتب التفضيل في
  قاعدة البيانات (عمود `locale` على `company_users`/`employees` — migration 21)،
  فتتبع اللغة الحساب على كل الأجهزة وكل التطبيقات.
- **SSR صحيح**: كوكي `pharmacy_locale` يُقرأ في root layout لرسم `html lang/dir`
  والقاموس من أول رسم (بلا وميض)، والاتجاه RTL/LTR يتبدل تلقائيًا.
- **كتالوجات مقسمة مساحات** (`src/i18n/messages/{locale}/{ns}.json`) بأي مفتاح ناقص
  يرجع للعربية تلقائيًا، مع سكربت تحقق `scripts/validate_messages.py`.
- **أرقام لاتينية دائمًا** (0-9) في كل اللغات عبر `i18n/format.ts` (قاعدة Task 47)،
  وأسماء الشهور وصيغ التواريخ تتبع لغة الواجهة.

## النشر على Vercel (مشروعان من نفس المستودع)

Vercel يستضيف الواجهات فقط؛ باك إند Go + PostgreSQL يبقيان على خادمك (أو
Railway/Fly/Neon). أنشئ **مشروع Vercel لكل تطبيق** بنفس المستودع:

| الإعداد | مشروع الإدارة | مشروع نقطة البيع |
|---|---|---|
| Root Directory | `frontend/apps/pharmacy-app` | `frontend/apps/pos-app` |
| Framework Preset | Next.js | Next.js |
| Build Command | `next build` (افتراضي) | `next build` (افتراضي) |

متغيرات البيئة لكل مشروع:

- `NEXT_PUBLIC_API_URL=/api/v1` — يبقي النداءات same-origin عبر بروكسي rewrites
  المدمج في `next.config.js` فلا CORS ولا مشاكل كوكيز بين الدومينين.
- `BACKEND_INTERNAL_URL=https://api.<نطاقك>` — عنوان الباك إند الذي يصبّ عليه
  البروكسي داخل Vercel (نفس القيمة للمشروعين).

بعد النشر اربط الدومينات من لوحة Vercel: `app.<نطاقك>` لمشروع الإدارة و
`pos.<نطاقك>` لمشروع نقطة البيع.

## ملاحظة صيانة

ملفات البنية المشتركة (`lib/api.ts`، `lib/permissions.ts`، بوابات
`components/permissions`، مكونات `components/ui`، خطافات `hooks/`) منسوخة
حاليًا بنسخة مطابقة من `pharmacy-app` (نفس نمط التطبيقات في هذا المستودع).
عند أي تعديل جوهري عليها في أحد التطبيقين يُراجع الآخر — ويظل المنطق
الأمني الفعلي مفروضًا من الباك إند على كل الأحوال.
